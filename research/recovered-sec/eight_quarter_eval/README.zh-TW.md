# 最近八季 SEC 營收候選實驗（繁體中文譯文）

> 本文件為相鄰 [README.md](README.md) 的繁體中文譯文。原文為受 recovery-manifest SHA-256 驗證保護的歷史封存資料，原檔與雜湊保持不變。以下保留當時情境、命令與限制；目前交接入口見 [HANDOFF.md](../HANDOFF.md)。

這是已執行、可重現的**未經人工篩選之確定性候選稽核**，不是正式擷取器，也不是準確性基準。固定的 30 家公司名單在 `roster.json`。每家發行公司使用截至 **2026-11-03** 可取得的 10-Q/10-K 申報中，最近八個報告期末。各公司財報季末不同。SEC 股票代號目錄儲存為 `company_tickers.json`。

## 執行

使用 Python 3.12 與 `lxml`（上層實驗使用的相依套件）：

    SEC_USER_AGENT='Your Organization your-real-contact@example.com' python run.py --workers 4
    python summarize.py
    python -m unittest -v test_run.py

新下載須使用真實操作者聯絡資訊。請求依程序控制間隔，嘗試三次並採退避等待。正式使用時一次只執行一個下載程序。已快取的來源快照會重用。預設截止日固定，不會自動變成今日。支援 `--as-of YYYY-MM-DD` 與 `--tickers AAPL,MSFT`。首次探索執行另下載 INTC；`summarize.py` 因其不在固定 30 家名單而排除。

## 實際方法

1. 下載 SEC submissions JSON，選取最近 9 個不重複的 10-Q/10-K 報告期末。第九份申報支援第八個報告期末的 Q4 重建。不會默默銜接前身 CIK。XOM 的新繼受公司 CIK 會刻意標記。
2. 下載原始 inline-XBRL HTML，保留 URL、accession、申報日期、位元組、SHA-256 與完整來源。
3. 使用先前先導實驗的廣泛 revenue/sales 概念解析器。保留原始文字、單位、decimals、scale、context、維度、fact ID、來源表格／列與來源行號。這也會誤收資料；**原始候選不是已驗證的營收觀察值**。
4. 每個報告期末以 70–126 天期間選取直接揭露季度資料項。絕不可只因結束日相同，就將九個月資料項當成 Q3。年度申報僅在全年與九個月資料項的概念、單位、維度簽章與起始日完全相同，且推導季度長度符合時才推導 Q4。保留兩個運算元及引用，不套用模糊成員對應。
5. 合併值相同的重複資料；對相同概念／單位／維度／期間鍵的衝突值予以拒絕。多維度 contexts 分開保留，不攤平成單軸組成。
6. 依概念、軸與精確季度期間分組單軸資料項。將加總與同概念的無維度營收候選比較；若無此候選，則使用其他允許清單中的無維度營收概念。保留所有候選總額與每次比較，不默默選取可能不完整的總額。已報導數值使用四捨五入容許誤差。跨概念相符僅屬候選，也可能巧合。
7. 使用可見且刻意簡單的名稱啟發式分類軸，保留原始軸與成員。**這不是已解析的父子會計階層。**Products 小計可能與詳細產品重疊；這類分組應不通過，不可宣稱準確。Presentation/calculation/definition linkbases、重編與敘述表格解讀仍是後續工作。

## 產物

- `data/TICKER/*.html`：精確原始 SEC 快照；`submissions.json`：探索回應。
- `outputs/TICKER.json`：每份申報的原始候選資料項，以及八季候選、Q4 原始運算元、核對分組與例外。
- `outputs/manifest.json`：固定 30 家公司名單的來源追溯清單。
- `outputs/company_summary.csv`：逐家公司覆蓋與失敗指標。
- `outputs/quarter_summary.csv`：每個可取得的發行公司財報季末一列。
- `outputs/quarter_candidates.csv`：候選值、引用及 Q4 運算元來源追溯。**不是乾淨的營收組成資料集。**
- `outputs/summary.json`：整體指標與逐家公司結果。
- `tests.log`、`run.log`、`run_rest.log`：執行證據。

## 如實解讀覆蓋情況

「已處理」表示已下載與解析，不代表正確。「有維度分組」表示單一軸下至少有兩個候選，不代表該軸是有效且完整的營收組成。「已核對相符」表示加總與至少一個候選總額一致，不代表語意正確、來源揭露完整或具獨立真值。一家公司可能地理分組 8/8 季核對相符，但產品組成仍失敗。

未取得或比對 TradingView 參考資料。不聲稱準確率、召回率、TradingView 一致性、模型成本、模型延遲或跨來源等價性。此測試架構未呼叫 LLM。實驗單獨檢視確定性擷取與期間／階層困難。

## 已知限制與如實放棄判定

- 解析器不是完整符合標準的 iXBRL 處理器。未解析轉換、延續、所有 nil 語意、實體識別碼、隱藏資料項或分類標準 linkbases。缺少／不支援的數值字串會列為錯誤，不會默默猜值。
- 分類標準／成員改名會阻止全年減九個月的比對。名稱完全相同也可能掩蓋業務定義變更；不保證語意連續性。
- 跨獨立申報推導 Q4，可能混用原始與重編基礎。運算元保持可見供審查，但不嘗試自動認證重編。推導的四捨五入容許誤差不是完整 XBRL 精度區間引擎。
- 常見 US-GAAP 合併營收標籤未涵蓋每種銀行、保險、REIT 或公用事業呈現。缺少允許清單內候選總額代表覆蓋缺口，不是營收為零。
- 無維度本身不證明合併實體範圍。多個發行實體與被投資公司資料項需要額外範圍檢查。
- submissions 選取器從 `filings.recent` 開始，少於九個報告期末時取得封存 submissions。真正的新發行公司仍可能歷史不足。
- 一個維度可能包含父項、葉節點與總計。來源表格／列與成員證據已保留，但階層解析仍明確列為尚未實作階段。

九項合成迴歸測試涵蓋期間長度選取、Q4 算術、成員精確比對不符時放棄判定、拒絕衝突重複、合併相同重複、拒絕重複計算、保留多軸、優先直接揭露 Q4，以及 16 週零售季度。它們驗證程式行為，不驗證每份申報擷取的正確性。

## 具體觀察到的失敗案例

- Apple Q3 FY2026：同一 ProductOrServiceAxis 包含 Products 78,678 百萬、Services 30,739 百萬，以及合計 78,678 百萬的四個個別產品類別。六項全加會造成錯誤重複計算。正確合併候選總額為 109,417 百萬。證據是 AAPL JSON 中原始資料項列，不是虛構的階層關係。
- P&G：部門營收同時使用 StatementBusinessSegmentsAxis 與 ConsolidationItemsAxis。僅處理單軸的擷取器即使已取得資料項，也會漏掉組成。基準揭露此限制，不將其視為未揭露。
- Costco：財報 Q4 為 16 週，近似曆季的 110 天上限會錯誤排除。最終條件支援 70–126 天，並包含專門迴歸測試。
- JPMorgan/Bank of America：因申報頻繁，近期 submissions 可能少於八季；需要封存 submissions。
- ExxonMobil：股票代號目錄 CIK 2115436 為歷史較短的繼受公司。銜接舊 CIK 34088 是獨立的身分／連續性決策，不是依股票代號名稱自動合併。

使用原始 10-Q/10-K 申報；未獨立解析 10-Q/A 與 10-K/A 修正申報。這對重編敏感的用途構成額外限制。

已觀察到的數值解析例外包括：兩個 Lilly `us-gaap:Revenues` 資料項文字顯示為「no」（FY2024）、兩個 Prologis 銷售代理人數顯示為「twenty」，以及一個空白 Tesla 備供出售證券資料項。這些保留為解析錯誤。Lilly 的營收文字轉換確實是解析器支援缺口，未虛構零值。
